# `data/corpus-20k/` — what is here, and what is not

This directory holds the Corpus 20k rebuild's evidence. **Only the summaries, reports, thresholds
and decision records are committed.** The corpus itself — page fields, questions, derived seeds,
registry matches and the overlap-measurement caches — stays on the workstation.

## Why the data is not in this repository

The full working tree is 3.56 GB tracked, with ten files over GitHub's 100 MiB hard limit (the
DuckDB measurement caches under `gate1b/runs-*/` and `gate2/html-text/live.ndjson`). Git LFS is not
installed. Nothing in the build or the test suite reads these files: production is loaded from the
workstation by `scripts/corpus-20k/load/materialise.ts` reading them locally over a TLS connection,
and `scripts/export/dataset.ts` never reads `data/corpus-20k`, so the corpus is outside the
export/agents digest chain. Committing it would buy nothing and cost a repository that cannot be
cloned.

## Where the full data lives

| Copy | Location |
| --- | --- |
| Full git history, every data file tracked | local branch `archive/corpus-20k-full-history` (tip `abbf36e`, 68 commits). Never pushed. |
| Working-tree archive | `rnawiki-backups/corpus-20k-data-2026-09-05/corpus-20k-data.tar.zst` (1.64 GiB, sha256 in the sibling `.sha256` file; `raw/` and `render/` excluded) |
| Fetched source payloads (`raw/`) | workstation only; every batch is recorded with its sha256 in `state.json` |
| Production database backup | `rnawiki-backups/corpus-20k-2026-09-05/` |

Restore either way:

```bash
zstd -dc "../rnawiki-backups/corpus-20k-data-2026-09-05/corpus-20k-data.tar.zst" | tar -C data -xf -
# or, for the tracked subset:
git checkout archive/corpus-20k-full-history -- data/corpus-20k && git reset -q data/corpus-20k
```

## How each excluded directory is regenerated

| Directory | Regenerated by | Notes |
| --- | --- | --- |
| `raw/` | the per-source fetchers under `scripts/corpus-20k/`, gated by `legal-gate.json` | never refetch a batch already recorded in `state.json` |
| `identity/canonical.ndjson`, `identity/stages/` | `scripts/corpus-20k/identity/resolve.py`, then `pass2.py` and `pass3.py` | `summary.json`, `decisions.ndjson`, the merge maps and `worked-examples.md` stay committed |
| `reconciliation/{matched,new,not-found}.ndjson` | the reconciliation step over `identity/canonical.ndjson` | `summary.json` and `dispositions.ndjson` stay committed |
| `suppression/assignments.ndjson` | `scripts/corpus-20k/suppression/assign.py` | `summary.json` stays committed |
| `tiers/model-assignment.ndjson` | `scripts/corpus-20k/tiers/assign-models.py` | `summary.json` and `promotion-rule.md` stay committed |
| `registry/` | `scripts/corpus-20k/registry/match.ts` against the local ClinicalTrials.gov snapshot | `summary.json` is regenerated with it |
| `fields/{longevity,clinical,development}/`, `fields/biomarker-vocabulary.json` | `scripts/corpus-20k/fields/extract-*.py`, `augment.py`, `epmc.py`, then `coverage.py` | the four coverage and per-model summaries stay committed |
| `derived/seed-*.ndjson`, `derived/indexes/` | `scripts/corpus-20k/derived/compute.py` | `fire-counts.json` stays committed |
| `questions/batch-*.ndjson` | `scripts/corpus-20k/questions/derive.ts` | `metrics.json` stays committed |
| `render/` | `scripts/corpus-20k/render/` against a local build | pure output |
| `gate1b/runs*/`, `gate1b/validation-v*/*.duckdb` | `scripts/corpus-20k/overlap/measure.py` and `gate1b_v2..v4.py` | the per-version `summary*.json`, `report*.md`, `threshold*.json`, `page-meta*.json` and `matched-per-page*.json` stay committed |
| `gate2/html-text/`, `gate2/lists*/`, the large `gate2/pages*/` dumps | `scripts/corpus-20k/gate2/fetch.py` and `extract.py` | `summary*.json`, `report*.md`, `samples.json`, `runs*/` and the small page dumps stay committed |
| `recovery/attempts.ndjson` | the Phase 1 recovery run | `summary.json` and `report.md` stay committed |
| `load/`, `phase5a-pre/`, `pass*-pre/`, `legal/counts/` | run artefacts and pre-load snapshots | never inputs to anything |

`state.json` is the resume ledger for every phase and batch; read it with
`npx tsx scripts/corpus-20k/status.ts`. Do not edit it by hand.
