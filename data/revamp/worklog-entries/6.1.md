### Phase 6 — step 6.1, the RSC payload

**What the measurement said, and why the primary option was not available.** The audit in
`data/revamp/payload-audit-before.json` (108 pages: the eight samples of step 0.3 and a 100-page
seeded draw from the build's own indexable set) found the dossier shipped twice — the flight stream
a median **54.5 %** of the served document, repeating **100 %** of the rendered record's text, live
text-to-HTML **0.048** against a 0.15 floor. Step 6.1's first instruction is to render the dossier
server-side and pass the client only the search bar's state. **That was already true**: every
component under `components/dossier/corpus/` was a server component, and the one client component,
the rail marker, took no props. The duplicate is not a component-boundary fault. Next.js inlines the
page's rendered element tree into the document on every render path a page can take —
`createInlinedDataReadableStream` is called unconditionally in
`next/dist/server/app-render/app-render.js` — and no configuration removes it. So the fallback the
step names was taken, in the form the corpus can carry: the two route families leave the page
pipeline and the server writes their documents itself, rather than 28,657 files being exported to
disk.

**The `'use client'` audit, since the step asks for it.** Thirty-one modules carried the directive;
thirty do now, and exactly one of them was in a corpus record's tree: `components/dossier/corpus/ContentsRailMarker.tsx`, which
took no props and read the DOM. It is deleted; its behaviour is `lib/island/rail.ts`. Every other
component under `components/dossier/corpus/` and `components/hubs/` was already a server component,
and their only client dependency was `next/link`, which is itself a client component and cannot be
rendered outside the page pipeline — eight files now use a plain `<a>`, which is also what a
document with no client router should emit. The rest of the directive's users are the React shell
(`AppShell`, `app-context`, `SiteHeader`, the three modals, `GoogleAnalytics`) and the pages that
need it — the review queue, the legacy dossier's contribution and comment controls, the home search.
A corpus document uses none of them: its header and footer are server components
(`components/document/`), and the search field, the rail marker and the analytics choice are the one
island. So the flight duplicate was never a component-boundary fault, and no amount of converting
would have removed it.

**A second measurement decided how much markup had to go with it, and separates this step's effect
from fix round 3's.** `payload-audit-before.json` was written against the v7 build, which predates
fix round 3. The build this step started from was re-measured over the same 108 pages in a browser
before a line was changed: live text-to-HTML **0.0467**, flight stream a median 64.6 % of the live
document, `<main>` 78,659 bytes, head 3,757, other scripts 3,023, header and footer 3,691,
`innerText` 11,534. Removing the flight stream and changing nothing else would have given
**0.1318** — under the floor. So the document's own shell and the record's markup had to come down
too, and the delta below is this step's plus fix round 3's, with the flight stream accounting for
0.0467 → 0.1318 of it and the markup for the rest.

**What was built.**

- `app/d/[slug]/route.ts`, `app/h/route.ts`, `app/h/[type]/[slug]/route.ts` — route handlers that
  render the record once and return a whole HTML document (`lib/corpus/document.tsx`,
  `lib/hubs/document.tsx`, `components/document/DocumentShell.tsx`, `lib/document/render.tsx`).
  No flight stream, no client chunks, no second copy of any text.
- `lib/island/` → `public/island/rnawiki-document.js`, bundled by `scripts/build-island.mjs` from
  `prebuild` and `predev`: the header's search field, the contents rail's marker, and the analytics
  choice. It is handed the search field's state and nothing of the record. It imports the search
  route, the medicine-type label and the analytics policy from the same modules the React shell
  imports, so the two renderers cannot drift on any of the three.
- `app/legacy-record/[slug]/page.tsx` — the React dossier, for the 29 slugs the corpus does not
  hold and for every end-to-end fixture. `/d/<slug>` forwards to it over loopback and returns
  exactly what it answered (`lib/document/legacy-forward.ts`); the reader's URL, canonical,
  indexing decision, 308 and 404 are unchanged. It answers 404 to anything that is not that
  forward.
- `app/d/[slug]/opengraph-image/route.tsx` — the same card at the same URL, as an explicit route
  now that the segment has no page.
- Markup: the disclosure row lost its `cd-row-head` wrapper and its `cd-row` class (the row is
  `.cd-rows > li`), rail links lost `cd-rail-link` and `data-corpus-rail` (the CSS reaches them
  through the rail; the island reads each link's own `href`), and `data-anchored` is written only
  when it is true. No text changed, no measured class was dropped, and
  `scripts/corpus-20k/gate2/browser-checks.ts` was moved onto the structural selector so its
  rail-link count keeps measuring what it was written to measure (it read 0 for one run; restored,
  it reads 68 focus targets and 102 keyboard stops on metformin).
- `app/layout.tsx` now imports the corpus stylesheets and `lib/fonts.ts`, so the layout's entry in
  the build manifest carries every stylesheet the document links and there is one copy of each face
  in the build.

indexable draw would otherwise move with the build):

| --- | --- | --- |

**The floor is met; the 0.25 target is not, and the reason is structural.** A median page's `<main>`
is 66 KB, of which **54 KB is inside closed `<details>`** — the technical disclosures §10 and §13(5)
require to be in the HTML for a reader who opens them and for a crawler that reads them. `innerText`
does not count that text, so it is denominator without numerator. Reaching 0.25 would need the
document at about 46 KB, which is less than the disclosures alone. Deferring them to a fetch would
clear the number and would take the evidence off the page for a reader without scripts; it was not
done. This is a decision for the lead, stated with the numbers rather than resolved here.
