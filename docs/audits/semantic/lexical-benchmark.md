# Retrieval benchmark for evidence reading units

Benchmark `semantic-retrieval/v1` · projector `semantic-units/v1` · lexical `semantic-lexical/v1` · gates `semantic-scope-gates/v1` · seed `20260902`.

## What this measures

Every query below was generated by template from one record name and one section or field
label; the correct answer is the sampled unit the template was built from. No person wrote a
query, so this measures retrieval over the corpus wording, not how people ask questions and
not whether a recorded reading is right.

The candidate pool is 2000 units drawn from 400 records, 5 units each, with a fixed
seed. Both retrievers see that same pool. The corpus holds 273110 units in total.
A template answered by two sampled units was dropped, which is why 1943 queries remain.

query holding one of those words beside another record name genuinely names two records.

## Pass rule for a vector index

A pgvector shadow index is added only when dense retrieval beats lexical retrieval on
recall@5 by at least 5 points absolute with the scope gates applied.

- Lexical recall@5 with gates: 0.933
- Dense recall@5 with gates: 0.956
- Pass rule met: no
- pgvector extension available on this server: no
- Vector index added: no

Dense embeddings came from `Xenova/bge-small-en-v1.5` run on the local CPU, cached under `/Users/admin/rnawiki-ingest-data/models`. Cosine similarity was computed by brute force over the pool.
