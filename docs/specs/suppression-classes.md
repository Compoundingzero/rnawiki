# Suppression classes (R2) — derived from data, never from judgement

**Status:** rule fixed 2026-09-04 (Fable). The executor (Opus) evaluates every canonical record
against these tests, writes `data/corpus-20k/suppression/assignments.ndjson` (one line per record:
`{ key, suppressed, classes: [...], evidence: [{test, source, value}], unknown: bool }`) and reports
the class list with counts before any page renders. **A record whose class cannot be determined
from any listed source is suppressed** (`unknown: true`), never released.

## What suppression does

For a suppressed record the derived sections **1 (bioavailability gap), 2 (N-of-1 designability)
and 6 (time-to-signal) do not exist** — not softened, not collapsed, absent from the data the
renderer receives. The page renders factual reference only: what it is, what it treats, what the
label says, what trials found. It carries one prominent statement, generated from the regulator's
own classification that triggered suppression, that the compound requires medical supervision —
worded as a register fact, never as advice (R14). Any other derived seed that could read as
guidance for a suppressed compound is dropped by the same flag.

supplement listing is unknown and stays suppressed until data arrives.

## Reporting before any page renders

`data/corpus-20k/suppression/summary.json`: per test the count matched; distinct suppressed count;
unknown count; cleared count; and 25 named examples per test for a person to sanity-check. The
worklog gets the table.

## Interaction with tiers and models

Suppression is orthogonal to tier. A Tier 1 longevity compound in a suppression class (e.g. a
scheduled substance) keeps the LONGEVITY model's factual fields and loses seeds 1, 2 and 6. A
suppressed record never renders "can I test this myself" in any wording.
