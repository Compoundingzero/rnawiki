# Release B backlog

Ordered by dependency. Nothing here should start before Release A ships, because most of it consumes
the repaired corpus and would otherwise be built against data that is about to change.

## 1. Regenerate all agent outputs against the repaired corpus

The ten agents in `data/agents/` were last run against the pre-repair corpus. Their inputs have moved
substantially — interaction signals alone went from a capped maximum of 12 to a maximum of 164, and
role denials from 1,724 to 7,261 — so every count they publish is stale.

Run `npx tsx scripts/agents/run-agents.ts --date=<YYYY-MM-DD>` and commit the diff.

## 2. Import current post-repair candidates through migration 0017

**Not the old 2,005.** Those were computed against the pre-repair corpus and are preserved as a dated
audit snapshot at `~/rnawiki-ingest-data/pre-repair-snapshot/`. Importing them would present stale
occurrences as live questions and spend reviewer effort on values the regeneration has already
changed.

The tables are in place: `agent_runs`, `agent_review_candidates`, `agent_queue_decisions`. The
identity contract is in `lib/agents/core/identity.ts` with 16 tests. What is missing is the code that
stamps a `candidateKey` and `occurrenceKey` onto each emitted candidate and writes the run.

## 3. Build the authenticated review-queue UI

Nothing renders the queue today. Until it does, the loop is open at the reader's end even though the
substrate exists.

## 4. Persist deterministic engine findings

**Verified during Release A: the `engine_findings` table exists and nothing writes to it.**
`scripts/apply-recorded-background.ts` prints findings to the console and discards them
(`apply-recorded-background.ts:25`).

Smallest honest path: record the run, not only the failures. A run that produces zero findings is
itself the fact worth keeping, because per-rule precision cannot be computed from failures alone —
the denominator is the number of times a rule ran and stayed silent.

## 5. Question-level `conflicting` and `stale`

`DossierQuestionCoverageState` still lacks both. The inputs now exist and are better than they were:
`comparisonState` distinguishes a genuine `differ` (231 fields) from `not_comparable` (12), so the
question layer can finally surface a real conflict without inheriting the old Boolean's false
positives. `stale` needs per-question freshness, which is still dossier-level.

## 6. `recordedBackground` in the public bulk export

`scripts/export/dataset.ts` makes no reference to it. The 33.5 MB excerpt-bound corpus is still
absent from the only bulk artifact the project publishes, while remaining extractable one row at a
time through a 60/min API.

This also clears the last red line in the audit: `data/manifest.json` still declares CC BY-SA 4.0
because it is regenerated by the exporter, so the licence-consistency check stays red until an export
runs against the authoritative database.

## 7. Complete independently validated chemistry

Phosphorus TPSA stays unpriced. The corpus holds one phosphorus record and it does not reconcile —
the module already sits 16.28 Å² above PubChem there before any phosphorus contribution, so adding
one would widen the gap. **Do not guess it from that record.** It needs an independent validation set.

Also open, found during the sulfur work and recorded rather than worked around: the shared
organic-subset valence rule hands an aromatic sulfur a hydrogen it does not have, so
`parseSmiles('c1ccsc1')` returns C4H5S for a C4H4S compound. The TPSA branch is ordered to avoid it;
the real fix belongs in the shared rule.

## 8. Restore and validate stereochemistry

All 144 `molecular-properties/v1` records carry connectivity-only SMILES because the build script
requests a property PubChem retired. The legacy CSV is the chemically richer layer — 1,370 of its
3,204 SMILES carry stereochemistry against 0 of 144 — which is the reverse of how both layers are
described.

## 9. Source-bound datasets UI and APIs

52 MB of agent output reaches no route, no page and no manifest.

## 10. ClinicalTrials.gov posted results

The largest unclaimed content asset: 48,065 interventional drug studies with posted results, each
carrying adverse-event tables with numerator and denominator per arm, against `pivotalResults`
holding 18 records. One 2.73 GB bulk download.

## Statement caps recorded during Release A and deliberately not changed

`MAX_USE_STATEMENTS` (3), `MAX_CONTRAINDICATION_STATEMENTS` (4) and `MAX_MECHANISM_STATEMENTS` (4)
truncate in **document order** rather than after a sort, so they do not carry the systematic bias the
interaction cap did. They are still canonical truncation and still silent. `MAX_ADVERSE_EVENTS` (20)
was checked and is not truncation at all — it refuses a match, because a list longer than twenty came
from a table run together rather than from one sentence.
